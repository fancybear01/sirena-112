# Импорт классификатора v046

Задача #32. Импорт выполняется один раз вне runtime. Kotlin Core (#33) и Python
AI (#35) используют `contracts/catalog/classifier-v046-11.json`. XLSX нужен
только для повторного импорта, а не для запуска приложения или тестов CI.

## Воспроизведение

Получите исходный XLSX из материалов задачи хакатона и положите в
`data/raw/classifier/`, сохранив исходное имя. `data/` уже в `.gitignore`.
Исходник не помещается в `models/` и не публикуется вместе с кодом.
Ожидаемый SHA-256:
`8d969b8e973a9574c63763ff290a11cb7221c50e5f9955efdb33520914d51409`.

Из корня репозитория (Python 3.9+):

```powershell
python -m pip install -r tools/classifier-import/requirements.txt
$source = (Get-ChildItem data/raw/classifier -Filter '*.xlsx' | Select-Object -First 1).FullName
python tools/classifier-import/import_classifier.py "$source"
python tools/classifier-import/examples.py
python -m pytest tools/classifier-import -q
```

Linux использует те же команды Python, вместо `$source` передайте путь к XLSX.
`--output-dir` позволяет писать результат в отдельный каталог для проверки
повторяемости. Генератор примеров принимает `--catalog` и `--output-dir`.
В результатах нет текущего времени и абсолютного пути. Одинаковые байты XLSX
с одинаковым именем дают побайтно одинаковые JSON. Версия/имя/дата/хеш источника
сохранены в metadata, каждая запись содержит лист, строку и исходные поля F:N.

## Модель данных

- `records` — 1281 происшествие, отсортированное в порядке исходных строк.
- `signIds` — три позиции иерархии; отсутствующий уровень сохраняется как null.
  ID — SHA-256 от группы, уровня, родителя и нормализованного текста, с префиксом.
  Одинаковый признак под разными родителями остаётся разным узлом.
- `columns` — 76 колонок O:CL. Каждая содержит стабильный `serviceId`, исходные
  заголовки и явное условие `all`. Пустое `all` означает без дополнительного
  условия заголовка. Пустая ячейка не создаёт правило.
- `routingRules` — ссылки на колонки, `NOTIFY` / `DO_NOT_NOTIFY`, тип происшествия
  у адресата, исходное значение. `sourceColumn` + номер строки однозначно
  восстанавливают адрес ячейки. Список главных служб не подменяет эти правила.
- `questions` — условия маршрутизации и свободный текст дополнительных вопросов
  из J. Текст J не разбивается на выдуманные варианты ответов и отмечен для
  методической проверки. ID условий и опций стабильны.
- `sections` — заголовки разделов и замечания в их служебных колонках.
  Замечания не наследуются молча всеми строками раздела: значение такого
  наследования должен подтвердить заказчик. Для финальной проверки маршрута
  Core должен учитывать наличие этих неразобранных замечаний.

`classifier.schema.json` валидирует каталог; `scenario.schema.json` и OpenAPI
0.3 валидируют уже сформированные учебные сценарии. Это разные структуры.

## Пустые значения и неоднозначности

21 пустой сценарий сохраняется как null со статусом `MISSING`, 9 явных
«без сценария» — null с `EXPLICIT_NONE`. Нестандартные непустые значения
сохраняются как `SOURCE_LABEL`. ЕКП-35 также может отсутствовать.
102 записи не имеют главной службы; несколько значений N преобразуются в
массив `mainServiceIds`. Неизвестный алиас — ошибка импорта.

741 значение «нет реагирования» в AA означает отрицательную ветку СМП для
условия «пострадавшие не на месте». Она не исключает происшествие или другие
службы. Состояния вопроса `routing.victims-status` взаимоисключающие:
`NONE`, `PRESENT`, `NOT_ON_SCENE`. Неотвеченный вопрос — неизвестное значение,
а не `NONE`/false. При одновременно совпавших положительном и отрицательном
правилах требуется разбор конфликта; глобальный приоритет запрета не задан.

Неясные условия (`>5 чел / ОД`, `пеш`, `ав`, отсутствующий перечень объектов
культуры) сохраняются с `requiresReview`. Совпавшее непроверенное правило
не должно автоматически определять итоговый маршрут. Отрицательный ответ
на однозначный вопрос может исключить соответствующую ветку. Для baseline
веток, зависящих от неясных признаков, также требуется проверка.
Условия внутри текста ячейки отмечаются отдельно. Отчёт показывает каждое
предупреждение со строкой и кодом происшествия; предупреждения не теряют строки.

Нормализация: Unicode NFKC, схлопывание whitespace, trim; для алиасов также
casefold. Сравнение служб выполняется по ID. Исходные написания сохраняются.
Служба 101, ОДС ПСЦ и МГПСС остаются разными адресатами; общий заголовок МЧС
не является основанием их объединять. Старые mock-списки Web/AI не являются
справочником и будут заменены в #34/#35.

Код проверяется арифметически: `Г*1000000 + п1*10000 + п2*100 + п3`.
72 исходных записи используют п3 > 99; они сохраняются с предупреждением,
а не обрезаются до двух цифр. Формулы XLSX не исполняются: допускается только
ожидаемая формула E, сверяются компоненты и сохранённое Excel значение.
Изменённые заголовки/формулы, дубликаты, неизвестные службы, повреждённая
структура и merged cells внутри данных вызывают понятную ошибку до экспорта.

## Проверки и примеры

Контрольные числа: 1281 записей, 21 MISSING, 9 EXPLICIT_NONE, 102 без главной
службы, 741 отрицательных правил, 0 дубликатов и неизвестных служб.
Числа относятся к указанному хешу источника, а не к произвольной новой версии.

Четыре синтетических сквозных fixture:

| Код | Категория |
| --- | --- |
| 1050602 | Дым в мусоропроводе |
| 2010000 | ДТП без пострадавших |
| 22010000 | Аллергия |
| 14010100 | Массовое отключение стационарной телефонной связи |

`examples.py` — проверочный интерпретатор условий и генератор fixtures;
production-движок реализуется в Kotlin в #33. Тесты проверяют каталог,
ссылочную целостность, ground truth, условное добавление СМП и запретную ветку,
повторяемость, отсутствие кеша формулы и ошибки входного XLSX. CI создаёт
маленькие синтетические XLSX с сохранёнными заголовками без доступа к исходнику.
Прохождение импорта не означает методического подтверждения всех маршрутов:
неразрешённые условия и замечания остаются видимыми в отчёте.
