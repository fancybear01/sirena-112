# AI Service

Python-сервис с локальными моделями.

Ответственность:

- генерация сценариев и эталонов;
- моделирование поведения абонента;
- классификация происшествия;
- анализ свободного текста и транскрипта;
- рекомендации по результатам занятия;
- STT/TTS либо адаптеры к локальным речевым процессам.

Сервис получает контекст через Kotlin Core и не имеет прямого доступа к
основной схеме PostgreSQL.

## Голосовой режим

Core сначала создаёт AI-сессию, передавая только разрешённый контекст сценария.
Затем Go Media подключается по `aiSessionId` к бинарному WebSocket и отправляет
PCM-аудио обучающегося. AI возвращает синтезированное PCM-аудио, транскрипт и
состояние AI-абонента. Управление Asterisk остаётся в Go.

Оценивание запускается отдельным запросом из Core после занятия. В карточном
режиме Go Media не участвует. Контракт голосового потока:
`contracts/media-ai.md`.

## Текущее состояние

Работает каркас сервиса и три эндпоинта с заглушками. Форма запросов и ответов
окончательная, Core может писать интеграцию прямо сейчас. Настоящие модели
подключаются внутри `app/engines` и контракт не меняют.

| Задача | Что даёт |
| --- | --- |
| #14 | каркас, схемы, три эндпоинта с заглушками |
| #15 | управляемое поведение абонента вместо `mock_dialogue` |
| #16 | содержательная оценка вместо `mock_scoring` |

## Запуск

```bash
cd services/ai
python3 -m venv .venv
.venv/bin/python -m pip install -e ".[dev]"
.venv/bin/python -m uvicorn app.main:app --port 8000
```

Документация API поднимается на `http://localhost:8000/docs`.

Тесты:

```bash
.venv/bin/python -m pytest
```

Переменные окружения: `AI_HOST`, `AI_PORT`, `AI_ENGINE` (сейчас только `mock`).

## Эндпоинты

| Метод | Путь | Назначение |
| --- | --- | --- |
| GET | `/health` | живость, версия и активный движок |
| POST | `/ai/scenarios/generate` | черновики учебных сценариев |
| POST | `/ai/dialogue/respond` | реплика AI-абонента |
| POST | `/ai/sessions/score` | объяснимый отчёт по занятию |

### Правила, на которые можно опираться

- Все поля наружу в camelCase.
- Незаполненные необязательные поля в ответ не попадают. Это требование
  `contracts/scenario.schema.json`, где для таких полей разрешён конкретный тип,
  но не `null`.
- Неизвестное поле в запросе это ошибка, а не молчаливое игнорирование.
- Ошибка приходит в том же формате, что и у Kotlin Core: `timestamp`, `status`,
  `code`, `message`, `path`, `requestId`, плюс `details` со списком полей.
- Заголовок `X-Request-ID` принимается и возвращается обратно; если его нет,
  сервис создаёт свой.
- Ответы детерминированы: одинаковый запрос даёт одинаковый результат.
  Для генерации это обеспечивается полем `seed`.

### Инварианты отчёта об оценке

1. Сумма `maxPoints` по критериям равна `maxScore`.
2. `totalScore` равен сумме `earnedPoints` минус сумма штрафов и не ниже нуля.
3. Каждый критерий не в статусе `PASSED` имеет запись в `errors` с кодом и
   понятным объяснением.

Эти правила проверяются тестами и должны сохраниться после подключения
настоящей модели оценки.

## Пример

```bash
curl -s localhost:8000/ai/scenarios/generate \
  -H 'Content-Type: application/json' \
  -d '{"category":"FIRE","difficulty":"BASIC","count":1,"seed":7}'
```

## Структура

```text
app/
  config.py            настройки и выбор движка
  schemas/             контракты запросов и ответов
  engines/             реализации: сейчас заглушки, позже локальные модели
  web/                 маршруты, middleware, обработка ошибок
tests/                 проверка контракта, инвариантов и ошибок
```

Каталог сценариев в `app/engines/mock_scenarios.py` собран из реальных билетов
ГБУ «Система 112», поэтому формат данных проверяется на настоящих
формулировках, а не на выдуманных примерах.
