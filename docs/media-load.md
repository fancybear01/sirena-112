# Локальная нагрузка голосового тракта

`scripts/load_voice_stack.py` запускает только `PJSIP/smoke-out`. Это локальный
SIP loopback в Asterisk: вызов действительно проходит через Core, Media,
Asterisk, RTP и (в режиме `ai`) отдельный WebSocket для каждого звонка. Скрипт
не принимает произвольный SIP-адрес и не звонит на реальные номера. Нужен
поднятый полный стек; fake ARI этим скриптом не используется.

После `bash scripts/stack.sh start` запустить из корня проекта:

```bash
set -a; source .env; set +a
python3 scripts/load_voice_stack.py --counts 5,10,20 --rate 5 \
  --max-active 20 --queue-size 20 --hold 12 --report voice-load-report.json
```

Для `MEDIA_MODE=echo` добавьте `--flush-after -1`: echo не принимает команду
`input.flush`. Для прогона с моделями оставьте `MEDIA_MODE=ai` и стандартный
`--flush-after 5`. При включённой авторизации Core передайте токен преподавателя
через `CORE_TEACHER_TOKEN`; внутренний токен Media берётся из
`CORE_MEDIA_SERVICE_TOKEN`. Указать другие адреса можно только на `localhost`.

Генератор ограничивает одновременно выполняемые вызовы параметром
`--max-active`; ещё `--queue-size` запросов могут ждать. Новая заявка сверх
этого лимита получает в отчёте явный `rejected: generator queue full`. Отказ
Core, Media или AI записывается отдельно с HTTP-кодом. Скорость поступления
задаётся `--rate` в вызовах в секунду. Стадии идут последовательно. В каждом
вызове Core создаёт собственные `sessionId` и `aiSessionId`, Media выдаёт
`callId`; повтор ID или несовпадение ID в Core-событиях проваливает прогон.
Сам Media ограничивает число зарезервированных звонков через `MEDIA_MAX_CALLS`
(по умолчанию 32 при диапазоне RTP 18000–18099) и сразу отвечает
`503 capacity_exhausted` при превышении лимита.

Отчёт содержит успешные/отклонённые/ошибочные вызовы, p50/p95 времени до
ответа, максимум одновременно активных, память Docker-контейнеров до/в пике/
после, а также ARI-каналы и мосты, оставшиеся после завершения. Проверяются
живой мост с SIP и externalMedia для каждого вызова и отсутствие принадлежащих
генератору мостов/каналов после него. Если Docker stats недоступен, `passed`
остаётся `false`: без памяти замер не закрывает приёмку. Ctrl-C/SIGTERM
завершает только созданные генератором сессии. Обычный звонок другого клиента
не трогается.

Успешный локальный запуск не равен замеру на целевой конфигурации. Для приёмки
сохраните JSON с целевой машины и отдельно прогоните одиночный smoke:

```bash
bash scripts/stack.sh smoke
```

Если 20 не набрались в `peakActive`, есть отказы, ошибки или оставшиеся ARI
ресурсы, отчёт показывает фактический предел, а задача остаётся открытой.
