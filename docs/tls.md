# TLS для браузерного доступа

Часть задачи #89. Дата: 29.09.2026.

**Задача #89 этим не закрывается.** Сделан один её пункт - шифрование
браузерного канала. Чего нет, перечислено в конце, и заявлять это как
сделанное нельзя.

## Что сделано

Шифрование канала «браузер - веб - Core». TLS завершается на том же nginx,
который отдаёт интерфейс, и оттуда запросы идут в Core по внутренней сети
compose.

| Проверено | Результат |
| --- | --- |
| версия протокола | TLS 1.3, шифр TLS_AES_256_GCM_SHA384 |
| TLS 1.0 и 1.1 | отклоняются |
| `/health` по HTTPS | 200 |
| API через шифрованный канал | 200 |
| `Strict-Transport-Security` | `max-age=31536000` |
| `X-Content-Type-Options` | `nosniff` |
| `X-Frame-Options` | `DENY` |
| профиль без TLS | не сломан, HTTP на 5173 работает |

Повторить:

```bash
python scripts/check_tls.py --url https://127.0.0.1:8443
```

## Как включить

```bash
sh scripts/make_tls_cert.sh
docker compose -f compose.yaml -f compose.tls.yaml up -d
```

Открывается на `https://127.0.0.1:8443`. Профиль без шифрования остаётся
на своём порту: `compose.tls.yaml` - наложение, а не замена. Так сделано
намеренно, чтобы демонстрация и CI не зависели от сертификатов.

## Сертификаты

В репозиторий не попадают: каталог `certs/` в `.gitignore`. В образ не
встраиваются - монтируются снаружи только для чтения.

| Файл | Права | Что это |
| --- | --- | --- |
| `certs/sirena.key` | 600 | закрытый ключ |
| `certs/sirena.crt` | 644 | сертификат |

`scripts/make_tls_cert.sh` выпускает самоподписанный на 397 дней. Срок
выбран не произвольно: браузеры не принимают серверные сертификаты со
сроком больше 398 дней.

SAN обязателен и он есть - `DNS:localhost`, `IP:127.0.0.1`. Без SAN
браузер отклонит сертификат, даже если согласиться на недоверенный.

**Смена.** Перевыпустить с `TLS_FORCE=yes` и перезапустить `web`. Скрипт
не перетирает существующий сертификат молча: без этого флага он показывает
срок действия и выходит.

**Контур заказчика.** Кладутся их файлы теми же именами, в конфигурации
менять нечего. Самоподписанный сертификат стенда браузер помечает
недоверенным - это ожидаемо и не является поломкой.

## Чего в #89 нет

Перечислено, чтобы не попало в материалы сдачи как выполненное.

**TLS между службами внутри контура.** Core, AI, Media и PostgreSQL
разговаривают по HTTP и открытым соединениям внутри сети compose. Шифрован
только браузерный канал. Наружу эти порты не публикуются, но задача
требует шифрования и внутренних каналов, и оно не сделано.

**Аудит действий.** Есть частично: таблица `auth_audit` пишет входы и
действия над учётными записями с полями actor, action, subject, outcome,
requestId. Требований задачи она не покрывает: изменения сценариев,
оценок и материалов, доступ к записям звонков.

**Хранение аудита не менее шести месяцев и контроль целостности журнала.**
Не реализовано. Срок хранения нигде не задан, защиты от правки записей нет.

**Запрет изменения балла без аудита.** Не реализовано.

**Минимизация персональных данных и модель угроз.** Проверки требований
149-ФЗ и 152-ФЗ как артефакта нет. Юридическую оценку без эксперта делать
нельзя, и заявлять соответствие - тем более.

**Шифрование хранимых данных.** Ни база, ни дампы, ни записи звонков не
шифруются. Про дампы отдельно написано в `docs/backup-restore.md`.

## Оговорка про смысл сделанного

Сам факт локальной сети TLS не заменяет - это прямо сказано в приёмке
задачи. Но и обратное верно: включённый TLS на браузерном канале не делает
контур защищённым, пока внутренние каналы открыты, аудит неполон, а данные
хранятся в открытом виде.

Поэтому правильная формулировка для материалов: «браузерный доступ
шифруется, остальные пункты безопасности не выполнены», а не «TLS есть».
