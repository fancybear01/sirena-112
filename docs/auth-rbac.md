# Доступ к Core (задача #82)

В обычном демо-режиме `CORE_AUTH_ENABLED=false` прежний выбор роли без пароля сохранён. Это **не** режим с разграничением доступа. Для приёмки прав задайте одновременно:

- `CORE_AUTH_ENABLED=true`, `VITE_AUTH_MODE=secure`;
- `CORE_BOOTSTRAP_ADMIN_USERNAME` и `CORE_BOOTSTRAP_ADMIN_PASSWORD` (не короче 12 символов) для первой учётной записи;
- `CORE_MEDIA_SERVICE_TOKEN` (не короче 32 символов) одинаковый у Core и Media;
- `AI_SERVICE_TOKEN` одинаковый у Core, Media и AI при использовании AI-сервиса.

Core в безопасном режиме не стартует без токена Media и, если таблица пользователей пуста, без учётных данных начального администратора. Пароли хранятся как хеши; ответы API их не возвращают. Файл `.env` с реальными значениями не коммитить. После первого запуска смена bootstrap-переменных не меняет уже созданную учётную запись. UI и Core должны работать через один origin с прокси `/api` и `/ws`, чтобы cookie-сессия и CSRF работали штатно.

| Действие | ADMIN | TEACHER | STUDENT |
| --- | --- | --- | --- |
| Создать группу/пользователя, блокировать, сменить роль | Да | Нет | Нет |
| Создать занятие для студента своей группы | Нет | Да | Нет |
| Читать занятие/отчёт, события WS | Все группы | Только своя группа | Только своё занятие |
| Старт/стоп занятия, звонок | Нет | Только своя группа | Нет |
| Заполнить/отправить карточку, читать назначения | Нет | Нет | Только своё занятие |
| Аналитика | Все группы | Только своя группа | Нет |

Маршруты `/internal/**` Core принимают только `Authorization: Bearer <CORE_MEDIA_SERVICE_TOKEN>` от Media. В безопасном режиме Media принимает такой же заголовок на внутренних командах Core. AI принимает `Authorization: Bearer <AI_SERVICE_TOKEN>` на HTTP `/ai/**` и WS `/internal/v1/voice/**`, если токен задан. Неправильный токен не должен попадать в логи.

Первый запуск: администратор через `POST /api/auth/login` входит, затем создаёт группы `POST /api/admin/groups` и пользователей `POST /api/admin/users`. У `TEACHER` и `STUDENT` обязательно должна быть существующая группа. Преподаватель запрашивает студентов своей группы через `GET /api/teacher/students`; при создании занятия `POST /api/teacher/sessions` передаёт `studentId`. Старые занятия без владельца не видны студентам и преподавателям в безопасном режиме.

Для изменяющих запросов сначала получите `GET /api/auth/csrf` и передайте возвращённый `token` в заголовке `headerName` вместе с cookie-сессией. Завершение сессии: `POST /api/auth/logout`. При блокировке или смене роли действующая сессия аннулируется на следующем запросе. Журнал входа, выхода, смены роли и отказов хранится в `auth_audit` без паролей.

Перед публичным развёртыванием нужны HTTPS и непустые секреты; демо-настройки Compose не предназначены для открытой сети. Тесты: `services/core/gradlew.bat test` и `apps/web` typecheck/test. Для Go и Python сервисов тесты запускаются их штатными инструментами в CI.
