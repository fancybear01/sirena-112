# Голос в поставочном образе: проверка и поправки

Проверка по задаче #130. Дата: 29.09.2026.

Прежние голосовые проверки - #72, #73, #91 - сделаны локально на macOS
с `piper-tts` 1.8.0. В поставку идёт другое: образ `Dockerfile.full` на
Python 3.11 с `piper-tts` 1.2.0. Здесь проверено то, что действительно
поедет заказчику.

## Что нашлось

**В образе не работало распознавание.** Образ поднимался, отвечал 200
на `/health`, но `speechAvailable: false` и `speech: "unavailable+piper"`.
Причина: `libvosk.so` слинкована с `libatomic`, а в `python:3.11-slim`
этой библиотеки нет. Речь превращалась в ошибку `speech.unavailable`.

Вылечено одной строкой в `Dockerfile.full`. Других недостающих библиотек
нет, проверено.

**Утверждение о лицензии в документах было неверным.** Подробности ниже.

## Что теперь работает

Образ собран заново, запущен с моделями, ничего руками внутрь не ставилось:

```
{"status":"ok","speech":"vosk+piper","speechAvailable":true,"speechSimulated":false}
/ready -> 200
```

Двухходовой разговор на живых записях, тот же скрипт, что в #73:

| Ход | Оператор сказал | Распознано | Абонент ответил |
| --- | --- | --- | --- |
| 1 | назовите адрес происшествия | дословно | Учебный адрес, дом 1! Приезжайте скорее! |
| 2 | пострадавшие есть помощь нужна | дословно | Пострадавших нет, но тут страшно! |

Версии внутри образа: Python 3.11.16, `piper-tts` 1.2.0 (MIT),
`vosk` 0.3.45. У Piper 1.2.0 метод называется `synthesize`, а не
`synthesize_wav` - ветка совместимости из #128 работает не в теории,
а на настоящей модели.

## Лицензии: две поправки

**Пакет.** У `piper-tts` лицензия зависит от версии: MIT до 1.2.0
включительно, дальше GPL-3.0-or-later. В `docs/ai-benchmark.md` было
написано просто "MIT", и на этом основании отвергнут Silero. Формулировка
исправлена. Замеры #13, #72, #73, #91 сделаны на 1.8.0, то есть на GPL.

**Голос.** Репозиторий голосов Piper под MIT, но карточка `ru_RU-irina`
называет источником данных RHVoice и лицензию датасета - Unknown.

| Голос | Источник данных | Лицензия данных |
| --- | --- | --- |
| irina (используется) | RHVoice | **Unknown** |
| denis | OHF-Voice | CC0 |
| dmitri | OHF-Voice | CC0 |
| ruslan | ruslan-corpus | CC BY-NC-SA |

Отвергнуть Silero за NonCommercial и взять голос с неизвестной лицензией -
непоследовательно. `dmitri` (CC0) проверен в том же образе: работает
заменой одной переменной окружения, кода менять не надо.

| | irina | dmitri (CC0) |
| --- | --- | --- |
| ход 1 | 1.42 с | 0.59 с |
| ход 2 | 0.65 с | 0.52 с |
| длина реплики | 3.65 с | 2.51 с |
| звук | 16 кГц, пик 32303 | 16 кГц, пик 32382 |

`dmitri` ещё и быстрее, и говорит короче - для взволнованного заявителя это
скорее плюс: в #13 отдельно отмечалось, что irina диктует слишком размеренно.

**Решение за командой, оно продуктовое.** irina женский, оба CC0 мужских,
женского с чистой лицензией в наборе нет. Техническая сторона готова к любому
выбору.

## Задержки в образе: числа хуже локальных

| Режим | Локально, #91 | В образе |
| --- | --- | --- |
| HTTP p95 | 0.14 с | 1.55 с |
| 20 сессий вразнобой | 0.67 с | 3.86 с |
| 20 сессий залпом | 3.80 с | 11.29 с |

Разница шестикратная, и списать её на версию Piper нельзя: по отдельности
компоненты в образе работают так же.

| | Локально | В образе |
| --- | --- | --- |
| распознавание 3.29 с речи | 0.402 с | 0.364 с |
| синтез реплики | 0.139-0.197 с | 0.204-0.259 с |

То есть один ход стоит столько же, а под одновременной нагрузкой образ
проваливается. Похоже на накладные расходы Docker Desktop на macOS: он
работает в виртуальной машине, и хотя контейнер видит 12 ядер, параллельная
работа идёт заметно медленнее.

**Это предположение, а не измерение.** Проверить его можно только на целевом
Linux-сервере, где контейнеру виртуальная машина не нужна. До такой проверки
числа из #91 надо считать верхней границей возможного, а не обещанием.

Отдельно: в образе 8 ГБ памяти против 18 локально, но при двадцати сессиях
расход был 834 МБ, так что память тут не при чём.

## Как повторить

```bash
docker build -f services/ai/Dockerfile.full -t sirena-ai-full .
docker run -d --name ai -p 8090:8090 \
  -v "$PWD/models:/models:ro" \
  -e AI_STT=vosk  -e AI_STT_MODEL=/models/vosk-model-small-ru-0.22 \
  -e AI_TTS=piper -e AI_TTS_MODEL=/models/ru_RU-dmitri-medium.onnx \
  sirena-ai-full

curl -s localhost:8090/health
cd services/ai && .venv/bin/python scripts/voice_two_turns.py --input <каталог с двумя wav>
.venv/bin/python scripts/ai_load.py --sessions 5,10,20
```

Модели в образ не входят и в репозиторий не выложены, монтируются снаружи.
Где их взять - `docs/voice-readiness.md`.

## Вывод

Поставочный образ теперь распознаёт и синтезирует живую речь. Обещать живой
голосовой разговор можно, и это проверено на том, что поедет заказчику,
а не только на машине разработчика.

Два вопроса остаются открытыми и оба не технические: выбор голоса по лицензии
и замер задержек на целевом Linux-сервере.
