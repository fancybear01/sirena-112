# Жизненный цикл сценария (#84)

В защищённом режиме преподаватель своей группы открывает в Web раздел «Создание и назначение сценариев». Возможны два источника черновика: предложение AI по категории/сложности или копия утверждённого сценария. До утверждения преподаватель меняет полный JSON сценария (название, профиль, норматив времени, признаки, ответы и рубрику), оставляет комментарий и проверяет эталон. Проверка использует `contracts/scenario.schema.json` и пересчитывает код/службы по официальному классификатору Core; несовпадение блокирует утверждение.

Статусы `DRAFT → APPROVED` хранятся в `scenario_workflow` (миграция V3). `revision` защищает от перезаписи параллельных правок. Утверждённая версия не редактируется: команда «Новая версия» создаёт отдельный черновик с новым ID и увеличенным `version`; занятия содержат снимок утверждённой версии. До утверждения сценарий не попадает в обычный каталог и не назначается. Преподаватель видит новые сценарии только своей группы; базовые контрактные примеры остаются общими.

Основные маршруты: `GET /api/teacher/scenarios/workflow`, `POST /drafts`, `POST /drafts/generate`, `PUT /{id}`, `POST /{id}/validate`, `POST /{id}/approve?expectedRevision=N`, `POST /{id}/fork`, `POST /{id}/assign`. Для назначения передают ровно одно поле — `studentId` либо `groupId`; Core создаёт карточные занятия для активных студентов своей группы. Студент видит только свои занятия через прежний `/api/student/assignments`. В защищённом режиме старый локальный пакетный импорт отключён, чтобы не обходить утверждение.

Студент может предложить вариант из своей **уже оценённой** карточки. Core повторно вычисляет эталон, сохраняет только признаки и варианты ответов; адрес заменяется фиксированным учебным значением. ФИО, телефон, свободный текст и введённый адрес не копируются. Предложение поступает как черновик `STUDENT` группе преподавателя и проходит тот же путь проверки и утверждения. Повторно отправить ту же сессию нельзя. Это не редактор произвольных студенческих сценариев: карточка должна пройти оценку и давать разрешённый код того же типа происшествия.

Сквозная проверка на реальном PostgreSQL и визуальные скриншоты Web должны быть подтверждены на целевом стенде перед закрытием задачи.
