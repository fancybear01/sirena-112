# Двухходовой разговор с настоящими моделями

Проверка по задаче #73. Подтверждение того, что живой голосовой AI работает
не на подменах, а на настоящем распознавании и синтезе.

Дата: 22.09.2026. Стенд: MacBook, Apple M3 Pro, 12 ядер, 18 ГБ.
Модели: Vosk small ru 0.22 и Piper ru_RU-irina-medium, обе локально.

## Вердикт

**Живой голосовой AI подтверждён.** Два хода разговора на человеческой речи,
настоящие транскрипты, разные по смыслу ответы, состояние копится между
репликами, звук пригоден для проигрывания в RTP.

## Прогон

Подавались две записанные человеческие реплики оператора - те же, что
использовались в замерах #13. Сценарий `1050602`, задымление мусоропровода.

```
речь: vosk+piper | доступна: True | подмена: False

ход 1: 08_op_address.wav (3.33 с речи)
   распознано : назовите адрес происшествия
   simulated  : False
   ответ      : Учебный адрес, дом 1! Приезжайте скорее!
   звук ответа: 124086 байт = 3.88 с
   обработка  : 0.57 с от конца реплики до полного ответа
   раскрыто   : address

ход 2: 09_op_victims.wav (3.50 с речи)
   распознано : пострадавшие есть помощь нужна
   simulated  : False
   ответ      : Пострадавших нет, но тут страшно!
   звук ответа:  99938 байт = 3.12 с
   обработка  : 0.46 с от конца реплики до полного ответа
   раскрыто   : address, victims
```

## Что именно проверено

**Распознавание настоящее.** Обе реплики распознаны дословно, `simulated: false`.
Подмены `ScriptedRecognizer` и `SilenceSynthesizer` в прогоне не участвовали:
скрипт отказывается работать, если сервис поднят без моделей.

**Ответы разные по смыслу.** На вопрос об адресе абонент назвал адрес,
на вопрос о пострадавших - ответил про пострадавших. Это не одна заготовка
на все случаи.

**Состояние копится между ходами.** После первого хода раскрыт `address`,
после второго - `address, victims`. То есть сессия помнит, что уже было
сказано, и второй раз адрес диктовать не станет.

**Звук пригоден для RTP.** Проверены заголовки и содержимое:

| Файл | Формат | Длительность | Пик | Ненулевых отсчётов |
| --- | --- | --- | --- | --- |
| reply-1.wav | 16000 Гц, моно, 16 бит | 3.88 с | 32303 из 32767 | 99% |
| reply-2.wav | 16000 Гц, моно, 16 бит | 3.12 с | 32468 из 32767 | 97% |

Это настоящая речь, а не тишина и не обрезки: сигнал занимает почти всю шкалу.
Частота ровно та, которую требует контракт с Media.

**Время обработки: 0.46-0.57 секунды** от конца реплики оператора до готового
ответа целиком. Бюджет паузы - 1.2 секунды, запас примерно вдвое.

**Карточный режим не затронут.** Классификатор, сценарии и оценка не менялись,
тесты проходят.

## Как повторить

```bash
cd services/ai

AI_STT=vosk   AI_STT_MODEL=<path>/models/vosk-model-small-ru-0.22 \
AI_TTS=piper  AI_TTS_MODEL=<path>/models/piper-irina.onnx \
  .venv/bin/python -m uvicorn app.main:app --port 8090

.venv/bin/python scripts/voice_two_turns.py --input <каталог с двумя wav>
```

Код возврата 0 - живой голос подтверждён. Код 1 - есть блокер, он печатается
списком.

Скрипт сохраняет ответы абонента в `/tmp/voice-two-turns/reply-1.wav`
и `reply-2.wav` - их можно послушать и убедиться самому.

Без указания `--input` берутся фикстуры из `tests/fixtures/voice`: они
синтезированы Piper и распознаются Vosk дословно. Для проверки транспорта
этого достаточно, но задача #73 требовала именно человеческую речь, поэтому
прогон выше сделан на записях участника команды.

Записи не выложены в репозиторий: это живой голос. Модели тоже не выложены,
`models/` в `.gitignore`. Как их получить - `docs/voice-readiness.md`.

## Что это значит для демонстрации

Обещать живой голосовой разговор можно. На целевой машине он работает
без интернета и без видеокарты.

Остаётся зависимость от Media: чтобы разговор шёл через настоящий телефон,
нужен мост RTP и PCM из задачи #53. Со стороны AI всё готово, памятка для
моста - `docs/voice-ws-for-media.md`.
