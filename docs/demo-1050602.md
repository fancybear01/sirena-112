# Демонстрация карточного сценария 1050602

Этот маршрут использует реальный Kotlin Core и Python AI. PostgreSQL, Asterisk и
Media для карточного режима не нужны. Исходный сценарий и ожидаемый ввод — один
файл: [`contracts/examples/scenario-1050602.json`](../contracts/examples/scenario-1050602.json).

## Подготовка

Нужны Java 17, Python 3.10+ и Node.js 20.19+. В трёх терминалах PowerShell из
корня репозитория:

```powershell
# Терминал 1: AI
python -m pip install -e ./services/ai
python -m uvicorn app.main:app --app-dir services/ai --host 127.0.0.1 --port 8090
```

```powershell
# Терминал 2: Core
cd services/core
.\gradlew.bat bootRun
```

```powershell
# Терминал 3: Web
npm --prefix apps/web ci
$env:VITE_API_MODE = 'api'
npm --prefix apps/web run dev
```

Если зависимости уже установлены, пропустите `pip install` и `npm ci`. Откройте
`http://localhost:5173/teacher`. Vite направляет `/api` в Core на порту 8080;
прямой URL Core в браузере и настройка CORS не требуются. Для проверки готовности:
`http://localhost:8080/ready` и `http://localhost:8090/health`. При запуске Core
на другом порту настройте Vite proxy и `CORE_AI_BASE_URL` соответственно.

## Автоматическая проверка

В четвёртом терминале из корня репозитория:

```powershell
python scripts/smoke_card_1050602.py --expect-ai
```

Скрипт без дополнительных Python-зависимостей дважды создаёт и запускает
занятие, проверяет назначение студенту, форму, сохранение карточки, расчёт,
отправку, отчёт преподавателя и назначения служб. Успех: одинаковая оценка
`100/100`, 8 критериев AI, код `1050602`, версия `046-2024-11-15`, 14 служб.
Несовпадение останавливает проверку с указанием шага. Тот же smoke запускается
в GitHub Actions (`demo / smoke`).

Без AI Core применяет локальную оценку. Остановите AI и запустите
`python scripts/smoke_card_1050602.py --expect-fallback`: проверка потребует
4 критерия. С флагом `--expect-ai` такой результат считается ошибкой —
проверка не маскирует недоступность AI.

## Показ в браузере (3–5 минут)

Для показа начните с только что запущенного Core: состояние сессий сейчас в
памяти процесса. Не запускайте smoke перед браузерным показом на том же Core,
иначе у студента появятся дополнительные завершённые назначения.

1. `/teacher`: выберите «задымление: мусоропровод», запустите занятие и покажите id.
2. `/student`: то же занятие и версия классификатора. Выберите «жилой дом →
   мусоропровод → дым»; после сохранения Core покажет код `1050602` и службы
   только для чтения.
3. Ответьте «Нет» на дополнительные вопросы, выберите «Признак не выбран» в
   поле «Пострадавшие / погибшие», заполните описание «Учебный пример:
   задымление: мусоропровод», адрес «Учебный адрес, дом 1», отметьте отсутствие
   пострадавших. Отправьте на оценку.
4. Покажите критерии, замечания и рекомендации. Балл может отличаться от
   автоматического `100/100`: время заполнения и пропущенные поля учитываются.
5. Обновите `/student`: отчёт останется. Вернитесь на `/teacher`: статус
   `SCORED` и балл видны после загрузки. Нажмите «Новое занятие» только после
   демонстрации — кнопка очищает локальный id у преподавателя.

Если AI не поднялся, не останавливайте показ: Core оценит карточку локально;
оговорите, что это резервный отчёт с 4 критериями. Голосовой маршрут Media в
этот карточный сценарий не входит.

## Известные ограничения

- Состояние Core сейчас хранится в памяти: обновление страницы безопасно,
  перезапуск процесса Core удалит сессии. После перезапуска преподавательская
  страница очистит устаревший локальный id при ответе `404`.
- Преподаватель восстанавливает последнюю сессию по id в своём браузере;
  автоматический поиск активной сессии с другого устройства ещё не реализован.
- Критерий приветствия в карточном режиме автоматически не проверяется.

Перед хакатоном капитану остаётся повторить эти команды на втором компьютере
и принять показ. Эти два человеческих пункта CI проверить не может.
