# Голосовой поток AI: памятка для Media

Короткая выжимка для задачи #53. Полный контракт - `contracts/media-ai.md`,
здесь только то, что нужно, чтобы написать мост и не гадать.

## Порядок действий

1. Core создаёт голосовую сессию и передаёт Media пару `sessionId` + `aiSessionId`.
2. Media открывает `ws://<ai>:8090/internal/v1/voice/{aiSessionId}?sessionId=...`
3. Первым сообщением - `stream.start`. До него звук не принимается.
4. Дальше кадры PCM по 20 мс, а когда оператор замолчал - `input.flush`.
5. В ответ приходит реплика абонента: транскрипт, текст, звук, состояние.
6. В конце - `stream.stop`.

## Что отправлять

| Когда | Что | Формат |
| --- | --- | --- |
| сразу после открытия | `stream.start` | JSON, текстовый фрейм |
| пока оператор говорит | звук | бинарный фрейм, PCM16 mono 16 кГц, по 640 байт |
| оператор замолчал | `input.flush` | JSON |
| оператор перебил абонента | `response.cancel` | JSON |
| звонок завершён | `stream.stop` | JSON |

```json
{
  "type": "stream.start",
  "audio": {"encoding": "pcm_s16le", "sampleRate": 16000, "channels": 1, "frameDurationMs": 20}
}
```

Определять конец фразы - задача Media. AI сам тишину не детектирует: он ждёт
`input.flush` и распознаёт всё, что накопилось с прошлого раза.

## Что ждать в ответ

После каждого `input.flush` приходит ровно такая последовательность:

| Порядок | Сообщение | Что в нём |
| --- | --- | --- |
| 1 | `transcript.final` | что расслышали за оператором, отметки времени, признак `simulated` |
| 2 | `response.started` | текст реплики абонента |
| 3 | бинарные фреймы | звук реплики, PCM16 mono 16 кГц, по 640 байт |
| 4 | `response.completed` | длительность ответа в миллисекундах |
| 5 | `caller.state_changed` | паника, доверие, терпение, раскрытые факты, `hangUp` |

`hangUp: true` означает, что абонент бросил трубку: занятие провалено,
поток закрывается, звонок нужно завершить.

Вместо этой последовательности может прийти `error` - см. ниже.

## Пример двух ходов

Настоящий вывод `scripts/media_client.py --expect-real`:

```
ход 1: operator-01-address.wav
   оператор : служба сто двенадцать назовите адрес происшествия
              simulated=False, 0-3285 мс
   абонент  : Учебный адрес, дом 1! Приезжайте скорее!
   ответ    : 200 кадров, 3982 мс
   состояние: паника 0.55, доверие 0.70, терпение 0.55, раскрыто address

ход 2: operator-02-victims.wav
   оператор : пострадавшие есть помощь нужна
              simulated=False, 3285-6199 мс
   абонент  : Пострадавших нет, но тут страшно!
   ответ    : 156 кадров, 3111 мс
   состояние: паника 0.50, доверие 0.70, терпение 0.50, раскрыто address, victims
```

Обрати внимание: отметки времени второго хода продолжают первый. Они считаются
по количеству принятого звука, а не по часам, поэтому один и тот же разговор
всегда даёт одинаковые числа.

## Отказы и коды закрытия

| Код закрытия WS | Причина |
| --- | --- |
| 4404 | пара `aiSessionId` и `sessionId` не найдена или не совпала |
| 4409 | к этой AI-сессии уже подключён другой поток |

| Код в `error` | Когда |
| --- | --- |
| `stream.not_started` | звук или команда пришли до `stream.start` |
| `audio.unsupported` | не `pcm_s16le` или не моно |
| `input.empty` | `input.flush` без звука |
| `input.too_long` | фрагмент длиннее 30 секунд, он отброшен |
| `speech.unavailable` | речевые модели не настроены |
| `message.unknown` | неизвестный тип сообщения |

Ошибка не закрывает поток: можно продолжать работу со следующего фрагмента.

## Режим без моделей

Если на машине нет моделей распознавания и синтеза, поток работает, но вместо
транскрипта приходит `error` с кодом `speech.unavailable`. Это **не поломка**,
а штатный режим: транспорт проверить можно, речь - нет.

Понять заранее можно двумя способами:

- `GET /health` покажет `speechAvailable` и `speechSimulated`;
- ответ на создание сессии несёт те же поля плюс текстовое `notice`.

Если `speechSimulated: true`, транскрипт синтетический, и каждый
`transcript.final` помечен `simulated: true`. За распознанную речь такой текст
принимать нельзя.

Как поставить модели - `docs/voice-readiness.md`.

## Чем проверить свою реализацию

В репозитории лежит клиент, который делает ровно то же, что должна делать
Media, и проверяет имена и порядок кадров:

```bash
cd services/ai
.venv/bin/python -m uvicorn app.main:app --port 8090   # в другом терминале
.venv/bin/python scripts/media_client.py
```

Код возврата 0 - протокол соблюдён, 1 - есть расхождения, они печатаются
списком.

Фикстуры речи оператора лежат в `services/ai/tests/fixtures/voice/`:
два файла PCM16 mono 16 кГц, на них можно проверять мост, не записывая
ничего самому. Они синтезированы Piper и распознаются Vosk дословно,
так что годятся и для проверки транспорта, и для прогона с настоящими моделями.
