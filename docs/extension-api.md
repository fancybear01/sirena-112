# API расширений: как подключить свой модуль

Работа по задаче #97. Дата: 29.09.2026.

Локальный модуль может читать данные об обучении через документированный
API, не зная ни внутренних классов Core, ни пароля к PostgreSQL. Изменить
что-либо через этот API нельзя.

## Почему отдельная поверхность

`/api/teacher` и `/api/student` предназначены человеку в браузере: они
держат сессию, проверяют CSRF и роль пользователя. Расширение - это
программа, у неё нет ни пользователя, ни сессии. Смешивать их в одном
пространстве значит либо ослабить правила для людей, либо навязать
программе непригодный способ входа.

## Правила

**Только чтение.** Менять бизнес-данные расширение не может. Для изменений
есть команды Core, которые проверяют переходы состояний и права. Иначе
расширение обошло бы правила, ради которых Core существует.

**Свой токен.** `CORE_EXT_SERVICE_TOKEN`, отдельный от токена Media: отзыв
доступа расширению не должен ломать телефонию. Приставка `Bearer`
обязательна.

**Версия в пути.** `/api/ext/v1`. Несовместимое изменение появится как `v2`,
а `v1` продолжит работать, пока её не объявят устаревшей.

**Личных данных не отдаём.** Ни имён, ни логинов, ни карточек, ни
транскриптов, ни эталонного ввода сценария. Расширению нужны факты об
обучении, а не о людях.

**Выдача постраничная.** Размер страницы не больше 200. Слишком большой
запрос не отклоняется, а урезается: расширение получит данные и увидит
фактический размер в ответе.

**Выключено, пока токен не задан.** Пустой токен означает 503, а не
открытый доступ. Молчаливое «проверять нечем, значит пускаем» - тот самый
случай, когда защита выглядит работающей и не работает.

## Методы

| Метод | Что отдаёт |
| --- | --- |
| `GET /api/ext/v1/meta` | версия, признак только для чтения, ограничения |
| `GET /api/ext/v1/scenarios` | сценарии без эталонного ввода |
| `GET /api/ext/v1/sessions` | занятия без карточки и без обучающегося |
| `GET /api/ext/v1/sessions/{id}/result` | баллы и критерии без текста для человека |
| `GET /api/ext/v1/sessions/{id}/events` | события без полезной нагрузки |

Полное описание с схемами - в `contracts/openapi.yaml`, раздел с путями
`/api/ext/v1`.

Ответ страницы всегда содержит `items`, `page`, `size`, `total` и
`requestId`. По `requestId` обращение сопоставляется с журналом Core.

### Что именно не отдаётся и почему

| Не отдаётся | Причина |
| --- | --- |
| `expectedInput` сценария | это ответ на задание, утечка позволила бы подсказать |
| карточка занятия | свободный текст и адрес, введённые обучающимся |
| `studentId`, имена, логины | расширению нужны факты обучения, не люди |
| `message` критерия и рекомендации | текст для человека, меняется без смены версии API |
| `payload` события | может содержать транскрипт речи обучающегося |

`groupId` отдаётся: по нему строятся сводки, и он не указывает на человека.

## Коды ответа

| Код | Когда |
| --- | --- |
| 200 | данные отданы |
| 400 | отрицательная страница или размер меньше единицы |
| 401 | токен не передан, без приставки `Bearer` или не тот |
| 404 | занятие или отчёт не найдены |
| 405 | метод не поддерживается: поверхность только для чтения |
| 503 | `CORE_EXT_SERVICE_TOKEN` не задан, поверхность выключена |

## Как подключить свой модуль

Интернет не нужен: всё внутри локального контура.

```bash
# 1. Задать токен Core и перезапустить его
CORE_EXT_SERVICE_TOKEN=<не меньше 32 символов> docker compose up -d core

# 2. Проверить доступ и посмотреть ограничения
curl -H "Authorization: Bearer <токен>" http://127.0.0.1:8080/api/ext/v1/meta

# 3. Запустить образец, он же контрактная проверка
CORE_EXT_SERVICE_TOKEN=<токен> python scripts/ext_api_client.py
```

`scripts/ext_api_client.py` - и образец, и проверка. Он читает `meta`,
проходит сценарии и занятия постранично, забирает результаты, а затем
пробует то, чего делать не должен: изменить данные, обратиться без токена
и с неверным токеном. Всё это обязано быть отклонено.

Прогон на живом стенде:

```
1. версия v1, только чтение: True, предел страницы 200
2. scenarios получено 4 записей, sessions получено 6 записей
3. получено результатов: 5
4. POST /scenarios -> 405, POST /sessions -> 405
5. без токена -> 401, неверный -> 401
6. модуль обращается к базе: нет
Контракт соблюдён
```

Отдельно проверено, что без настроенного токена оба обращения дают 503,
а обычные методы Core при этом работают.

## Что проверяется автоматически

`services/core/src/test/kotlin/ru/sirena112/core/ext/ExtensionApiTest.kt`,
16 проверок: состав полей и отсутствие личных данных в каждом ответе,
постраничная выдача без повторов и с урезанием размера, отказы на
отрицательной странице и нулевом размере, 404 на отсутствующий отчёт и
неизвестное занятие, поведение токена во всех вариантах.

Отдельно закреплено главное: **при пустом токене поверхность закрыта.**
Это единственная проверка, из-за отсутствия которой защита могла бы
выглядеть работающей и не работать.

## Найдено по дороге

**Фильтр принимал токен без приставки `Bearer`.** `removePrefix` оставляет
строку как есть, если приставки нет, и работали два формата, один из
которых нигде не описан. Поймал тест, исправлено: приставка обязательна.

**Неверный метод отдавал 500 вместо 405.** Обработчик ошибок Core ловил
`Exception` целиком, и `HttpRequestMethodNotSupportedException` попадал в
«Внутренняя ошибка сервиса». Это же было отдельной находкой в проверке
форматов #98: `GET /api/teacher/sessions`, где есть только `POST`, выглядел
как падение Core. Добавлен обработчик - теперь оба случая отвечают 405
с понятным текстом.

**В Kotlin блочные комментарии вкладываются**, в отличие от Java. Путь
вида `api/ext` со звёздочками внутри комментария открывал вложенный
комментарий и оставлял внешний незакрытым - сборка падала с «Unclosed
comment» в конце файла.

## Ограничения

- Поверхность только для чтения, и расширять её на запись не планируется:
  для изменений есть команды Core.
- Фильтра по группе нет: расширение видит занятия всех групп. Личных
  данных при этом не получает. Если понадобится разграничение по группам,
  это отдельная работа и, скорее всего, отдельный токен на группу.
- Ограничения по частоте обращений нет. Защита от перегрузки сейчас -
  только предел размера страницы.
- Событий занятия отдаётся тип и время, но не содержимое. Расширению,
  которому нужен транскрипт, этот API не подойдёт, и это осознанно.
