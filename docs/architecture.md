# Архитектура

## Основной принцип

Kotlin Core является единственным источником бизнес-состояния. Остальные
компоненты выполняют специализированные операции и возвращают результат в Core.

```text
React SPA -> Kotlin Core -> PostgreSQL
                 |  |
                 |  +-----------------------> Python AI
                 |                              ^     |
                 |                              | WS  | PCM + metadata
                 v                              |     v
              Go Media <------------------------+-----+
                 |
                 | ARI + RTP
                 v
              Asterisk <-> SIP-клиент
```

Kotlin Core оркестрирует учебную сессию, но не проксирует аудио. В голосовом
режиме Go Media и Python AI взаимодействуют напрямую по потоковому соединению.

## Границы компонентов

### Web

Отображает состояние, отправляет действия пользователя и подписывается на
события. Не содержит правил оценивания.

### Core

Хранит пользователей, роли, сценарии, назначения, сессии, карточки, события и
отчёты. Управляет конечным автоматом сессии и интеграциями.

### Media

Управляет SIP-звонками и аудиопотоком. Получает RTP от Asterisk, приводит звук
к согласованному PCM-формату, отправляет его в Python AI и возвращает
синтезированный звук в звонок. Пересылает транскрипт и медиасобытия в Core.
Не читает основную БД, не знает эталон и не выставляет оценку.

### AI

Генерирует и анализирует содержимое по переданному контексту. Не публикует
сценарий без подтверждения преподавателя и не изменяет итоговую оценку напрямую.
В голосовом режиме выполняет STT, формирует реплику AI-абонента и выполняет TTS,
но не управляет Asterisk или жизненным циклом звонка.

## Голосовой поток Go <-> Python

Для MVP используется один бинарный WebSocket между Go Media и Python AI.
Контрольные сообщения передаются как JSON, аудио — бинарными PCM-фреймами.
Детальный формат описан в `contracts/media-ai.md`.

```text
1. Core -> AI:    создать AI-сессию с разрешённым контекстом сценария
2. AI -> Core:    вернуть aiSessionId
3. Core -> Media: call.start(sessionId, aiSessionId, SIP-адрес)
4. Media -> AI:   открыть voice WebSocket для aiSessionId
5. Asterisk -> Media -> AI: RTP -> PCM голоса обучающегося
6. AI -> Media -> Asterisk: PCM -> RTP реплики AI-абонента
7. AI -> Media -> Core: транскрипт и служебные события
8. Core -> AI:    запросить оценивание после завершения занятия
9. Core:          сохранить события, отчёт и итоговую оценку
```

Go является единственной медиаграницей для Core: Python возвращает транскрипт
в поток Go, а Go публикует `transcript.*` в Core. Благодаря этому Python не
должен знать адрес Core во время звонка, а Core не обрабатывает аудиофреймы.

В карточном режиме Media и Asterisk не участвуют: Core вызывает AI напрямую
для генерации, проверки или объяснения результата.

## Владение данными

- Core единолично владеет основной схемой PostgreSQL.
- Media работает с временным состоянием звонка и не подключается к PostgreSQL.
- AI получает только разрешённый контекст от Core и хранит состояние по
  `aiSessionId` в памяти. Если позже потребуется постоянное AI-хранилище, оно
  должно быть отдельным и не давать доступ к таблицам Core.
- `sessionId` связывает бизнес-сессию, звонок и события; `aiSessionId` является
  техническим идентификатором и не заменяет `sessionId`.

## Обязательные свойства

- локальный изолированный контур;
- TLS и RBAC;
- аудит значимых действий;
- восстановление сессии после краткого сбоя;
- заменяемые AI-модели;
- работа без внешних облачных сервисов.
