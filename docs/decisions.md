# Журнал архитектурных решений

## ADR-001: Монорепозиторий

Статус: принято.

Все компоненты, контракты и инфраструктура хранятся в одном репозитории для
быстрой интеграции и воспроизводимой демонстрационной сборки.

## ADR-002: Kotlin Core владеет бизнес-состоянием

Статус: принято.

Только Core обращается к основной схеме PostgreSQL. Media и AI получают данные
через внутренние API.

## ADR-003: Один frontend для трёх ролей

Статус: принято.

Администратор, преподаватель и обучающийся используют один React SPA с RBAC и
отдельными маршрутами.

## ADR-004: Локальный AI

Статус: принято.

Итоговая сборка не зависит от внешнего интернета. Провайдеры STT, TTS и LLM
должны заменяться конфигурацией.

## ADR-005: Локальный SIP

Статус: принято.

Asterisk используется как SIP-сервер. Go Media Gateway управляет звонком через
ARI и обменивается аудио по RTP.

## ADR-006: Прямой голосовой поток Media–AI

Статус: принято.

Kotlin Core создаёт AI-сессию и передаёт её идентификатор в команде запуска
звонка. После этого Go Media напрямую обменивается с Python AI аудио и
метаданными по бинарному WebSocket. Core не проксирует аудио, а Python не
управляет звонком. Транскрипт возвращается в Core через Media.

Для MVP выбран WebSocket вместо одновременной поддержки WebSocket и gRPC.
Протокол можно заменить без изменения бизнес-модели Core.
