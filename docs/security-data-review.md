# Какие данные система хранит и что с ними защищено

Артефакт по задаче #89. Дата: 29.09.2026.

**Это не юридическое заключение.** Соответствие 149-ФЗ и 152-ФЗ подтверждает
эксперт, а не разработчик. Здесь другое: перечень данных, которые система
действительно держит, и честная отметка, что у каждой группы защищено, а что
нет. Без такого перечня разговор о соответствии беспредметен.

Проверяемость: разбор ниже подтверждается прогоном
`scripts/check_personal_data.py`.

## Какие данные есть

### Персональные данные сотрудников

| Что | Где | Зачем |
| --- | --- | --- |
| логин, отображаемое имя, роль, группа | таблица `auth_accounts` | вход и разделение прав |
| хеш пароля | там же | проверка входа |
| входы и действия над учётками | таблица `auth_audit` | разбор инцидентов |

Больше ничего о сотрудниках не хранится: ни телефонов, ни должностей,
ни адресов. Это осознанный минимум.

### Учебные данные

| Что | Где | Персональные данные |
| --- | --- | --- |
| сценарии | `scenarios`, файлы в `contracts/examples` | нет, данные синтетические |
| карточки обучающихся | `training_sessions.card_body` | адрес и описание вводит обучающийся |
| отчёты об оценке | `session_reports` | привязаны к учётной записи |
| назначения служб | `service_assignments` | нет |
| записи занятий | том `voice-recordings`, файлы WAV | голос обучающегося |
| транскрипты | события сессии | речь обучающегося текстом |

### Данные заявителей: их нет

Абонента играет AI по синтетическому сценарию. Настоящих обращений в
систему-112 в ней нет и быть не должно. В примерах сценариев поле заявителя
пустое - проверено.

**Сценарий из карточки обучающегося** создаётся с явным запретом переносить
свободный текст, имена, телефоны и введённый адрес - это стоит в коде
`ScenarioWorkflowController` и не только комментарием.

## Что защищено, а что нет

| Данные | Разграничение доступа | Шифрование канала | Шифрование хранения |
| --- | --- | --- | --- |
| учётные записи и роли | да, роль ADMIN | браузер да, внутри нет | **нет** |
| пароли | хранится только хеш | то же | хеш, не шифрование |
| карточки и отчёты | да, своя группа | то же | **нет** |
| записи занятий | да, преподаватель группы и ADMIN | то же | **нет** |
| журнал аудита | доступ через базу | то же | **нет** |
| резервные копии | права 700 на каталог | - | **нет** |

Разграничение доступа реально работает: преподаватель видит свою группу,
обучающийся - только свои занятия. Записи занятий Media наружу не отдаёт
вовсе, только Core и только владельцу группы или администратору.

## Минимизация: что проверяется автоматически

`scripts/check_personal_data.py` проверяет три места.

**Файлы репозитория.** Примеры сценариев, фикстуры, тестовые данные,
каталог классификатора - 17 файлов. Ищутся телефоны, адреса электронной
почты, СНИЛС. Найдено: ничего.

**Ответы работающего сервиса.** Внешнее табло и аналитика не должны
раскрывать имена, логины, телефоны, адреса, транскрипты и карточки. В коде
`TrainingBoard` это обещано комментарием; проверка подтверждает, что
обещание выполняется. Найдено: ничего.

**Журналы контейнеров.** Ищутся пароли, токены и следы сырого звука.
Найдено: ничего.

Проверено, что проверка работает: подсунутые в файл телефон и почта
находятся оба.

Шаблона паспортных данных в проверке намеренно нет. Он неизбежно ловит любые
десять цифр подряд - коды классификатора, куски хешей - и превращает отчёт
в шум, который перестают читать. Паспортных данных в системе не ходит.

## Чего не сделано

Перечислено, чтобы это не попало в материалы как выполненное.

**Шифрование хранимых данных.** Ни база, ни резервные копии, ни записи
занятий не шифруются. Защита - только права доступа и то, что порты привязаны
к локальному адресу.

**TLS между службами внутри контура.** Шифрован только браузерный канал,
см. `docs/tls.md`. Core, AI, Media и база разговаривают по открытым
соединениям внутри сети compose.

**Аудит полон только по учётным записям.** Изменения сценариев, оценок и
материалов, а также доступ к записям занятий в журнал не пишутся.

**Хранение аудита шесть месяцев и контроль целостности журнала.** Срок
нигде не задан, защиты от правки записей нет. Значит утверждение «критичные
действия трассируются» верно только для входов и учётных записей.

**Запрет изменения балла без аудита.** Не реализовано.

**Модель угроз как формальный документ.** Этот файл - перечень данных и
состояния защиты, а не модель угроз по методике ФСТЭК. Составлять её должен
специалист по защите информации.

## Что это значит для формулировок

Правильно: «разграничение доступа по ролям работает, браузерный канал
шифруется, персональные данные минимизированы и это проверяется
автоматически; шифрование хранения и внутренних каналов не реализовано,
аудит полон только по учётным записям».

Неправильно: «требования 149-ФЗ и 152-ФЗ выполнены». Такое утверждение
требует эксперта и не подтверждается ничем из перечисленного выше.
